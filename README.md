# 頭痛ダイアリー（音声問診つき）

片頭痛のある方が発作を記録して、**受診のときに先生に見せる**ためのダイアリーアプリです。
就活ノート（ペーパーデザイン）と、AI問診メモアプリ「ココマデ」（音声問診・記録主義）の考え方を応用しています。

## 3つの中核体験

1. **音声問診** — 最初に普段の言葉で自由に話すと内容を整理し、不足している大切な項目だけを追加で質問する（頭が痛いときに画面を注視しなくていい）
2. **月間カレンダー** — 頭痛の日が強さの色で一目でわかる。薬を飲んだ日には💊マーク
3. **受診メモ** — 頭痛日数・服薬日数・よくあるきっかけを自動集計。**印刷して渡す**ほかに、**QRコードを受付で読み取ってもらう**こともできる（まとめ＋直近の記録をテキストで収録。専用アプリ不要、カメラをかざすだけ）

## 使い方

ビルド不要。`index.html` をブラウザで開くだけで動きます（音声問診は Chrome 推奨）。

1. **記録する** — 「🎤 問診をはじめる」を押し、まず頭痛について自由に話す
   - 頭痛がなかった日は「きょうは頭痛なし」だけで記録
   - 始まった時間 / 続いた時間 / 強さ / 場所 / 痛み方 / 動くと悪化するか / 痛む前の見え方の変化 / 吐き気と嘔吐 / 光・音 / 誘因 / 頭痛時の薬・服用タイミング・効果 / 生活への影響 / メモ
   - 自由な発話から拾えた項目は聞き直さず、不足項目だけを質問
   - 「自然な会話とメモ整理のため、回答をAIへ送信することに同意する」を選ぶと、普段の言葉をOpenAI APIで記録項目へ整理する
   - AIが整理した内容は、発話中に根拠がある項目だけをアプリ側で再検証して保存する（「昨日の夜から」→日付を昨日に）
   - AIへ同意しない場合、APIキー未設定、オフライン、APIエラーの場合は、端末内のルールベース解析へ自動的に切り替わる
   - マイクが使えない環境でも、**クイックボタン＋文字入力で全質問に回答できる**
   - 「🔊 質問読み上げON/OFF」で質問の読み上げを切り替えられる
2. **カレンダー** — 月の頭痛日数・服薬日数を集計。頭痛の薬を飲んだ日が月10日以上になると、薬の種類によって目安が異なることを説明し、医師への相談を案内
3. **受診メモ** — 過去1/3/6ヶ月の記録一覧と集計。「🖨 印刷して持っていく」で印刷用レイアウトに、「📱 QRコードで見せる」で読み取り用QRを表示（内容が多いときは直近分に自動調整）

## 記録項目（日本頭痛学会式ダイアリーの主要項目に対応）

頭痛日・頭痛なしの日・強さ（軽い/中くらい/強い）・部位・痛み方・持続時間・動作による悪化・痛む前の見え方の変化・吐き気・嘔吐・光音過敏・誘因（寝不足/天気/生理/ストレス等）・頭痛時の服薬状況と効果・生活への影響・メモ

## 構成

| ファイル | 内容 |
|---|---|
| `index.html` | 【患者用】記録（音声問診/フォーム）・カレンダー・受診メモの3画面 |
| `reception.html` | 【受付用】QRリーダー。カメラで読み取り→表示→印刷。保存・送信はしない |
| `styles.css` | 和紙×明朝のペーパーデザイン（就活ノート系譜）・印刷用CSS |
| `app.js` | 問診エンジン・AI出力の検証・ローカル解析・集計・音声入出力（Web Speech API） |
| `functions/api/interview.js` | 【サーバー】自然な回答をStructured Outputsで記録項目へ変換する問診API |
| `functions/api/summarize.js` | 【サーバー】メモ要約API。OpenAI APIへの中継（キーはシークレット） |
| `tests/app-parsers.test.cjs` | ローカル解析・AI出力適用・記録集計のテスト |
| `tests/interview-api.test.mjs` | 問診API・厳密なJSON Schema・推測防止処理のテスト |

## デプロイ（Cloudflare Pages）

フロントエンドはビルド不要。患者用はCloudflare Pages Functionsを含み、受付用とは別プロジェクトで配信している。

- **患者用（main版）**: https://zutsu-diary.pages.dev/
- **患者用（Codex版）**: https://zutsu-diary-2.pages.dev/ （index.html + styles.css + app.js + functions）
- **受付用**: https://zutsu-reception.pages.dev/ （reception.html を index.html として + styles.css）

更新手順:

```
npx wrangler login   # 初回のみ
mkdir -p dist-patient dist-reception
cp index.html styles.css app.js dist-patient/
cp reception.html dist-reception/index.html && cp styles.css dist-reception/
npx wrangler pages deploy dist-patient   --project-name=zutsu-diary-2   --branch=Codex
npx wrangler pages deploy dist-reception --project-name=zutsu-reception --branch=main --commit-dirty=true
```

`zutsu-diary-2`の本番ブランチは`Codex`。患者用はリポジトリ直下から実行し、`functions`も一緒にアップロードする。
受付用にはAI APIが不要なので、受付用だけを更新するときは`dist-reception`内からデプロイする。
カメラ（QR読み取り）とマイク（音声問診）は HTTPS が必要 → pages.dev はHTTPSなのでそのまま動く。

## 設計原則（ココマデから継承）

1. 回答・集計は**本人の記録からのみ**つくる。診断・推測はしない
2. 音声が使えない環境でも、ボタン＋テキストで全機能が動く
3. 記録は端末の localStorage に保存し、JSONで書き出し/読み込みできる
4. 本人が画面で明示的に同意した場合だけ、問診回答と長いメモをAI APIへ送る。初期状態はオフ
5. 旧版の「メモ要約のみ」の同意を、新版の「全回答のAI解釈」の同意へ自動的に拡張しない
6. AIの構造化結果をそのまま保存せず、発話に根拠がある項目・許可した値だけをアプリ側で再検証する

## 自然なAI問診とメモ要約（OpenAI API・任意機能）

本人が画面で同意した場合に限り、各問診回答をAIが意味で読み取り、一度の発話から分かった項目を整理する。既に分かった項目は聞き直さず、不足項目だけを質問する。40文字以上の「先生に伝えたいこと」は、保存後に医師向けの短い文章も追加する。初期状態ではAIへ送信しない。

- `functions/api/interview.js`: 問診回答をOpenAI APIへ中継し、厳密なJSON Schemaを指定したStructured Outputsで記録候補を取得する
- `functions/api/summarize.js`: 長い自由メモを医師向けに短く整理する
- モデルは `gpt-4o-mini`。APIキーはCloudflare側だけに置き、ブラウザやGitHubには渡さない
- JSON Schemaで型・必須項目・列挙値・追加項目禁止を指定し、その後さらに発話との整合性をコードで確認する
- AIが「昨日」を今日として返す、話していない持続時間や生活への影響を埋める、動作悪化をきっかけとして扱う、などの誤りを検証処理で除外する

- 有効化: Cloudflareダッシュボード → `zutsu-diary-2` → Settings → Variables and Secrets で
  暗号化シークレット `OPENAI_API_KEY` を追加（CLIなら `npx wrangler pages secret put OPENAI_API_KEY --project-name=zutsu-diary-2`）。必要に応じて再デプロイする
- キー未設定・オフライン・エラー時は端末内のルールベース解析で問診を続行し、メモは原文のまま保存する
- 同一サイト以外から問診APIを呼ぶブラウザリクエストは拒否する
- 話した原文は内部の `memoSpokenRaw` に保持し、「うーん」「えっと」などを除いた読みやすい文章を `memo` に保存する。AIの短いまとめは `memoSummary` に分けて保存する

## 割り切り（プロトタイプ）

- 音声認識・合成は Web Speech API（Chrome 推奨）
- AIへの同意がある場合はOpenAI API、同意がない場合や通信できない場合はローカルのルールベースで日常の言葉を解釈する
- AIの出力形式はStructured Outputsで固定するが、内容の正しさは保証されないため、保存前のコード検証を必須とする
- データ同期・アカウントなし（実証版では Supabase を想定）

⚠ このアプリは記録の道具であり、診断はしません。いつもと違う突然の激しい頭痛・手足のしびれ・ろれつが回らない等があるときは、すぐに医療機関へ。
